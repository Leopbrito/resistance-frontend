# Internacionalização

- Idiomas: `en` (padrão) e `pt-BR`, em `src/app/i18n/locales/`. A configuração está em `src/app/i18n/index.ts`.
- Uso: `const { t } = useTranslation();` e `t("grupo.chave")`. Nunca escreva texto visível direto no JSX (nem "CONNECTING...", issue #12).
- **Toda chave nova entra nos dois arquivos.** `src/app/i18n/i18n.test.ts` falha se faltar chave, se sobrar chave ou se os `{{placeholders}}` divergirem.
- Chaves em `camelCase`, agrupadas por tela ou tema: `home`, `join`, `lobby`, `roles`, `voting`, `players`, `tracker`, `common`, `errors`, `session`.
- Plural usa sufixos do i18next: `players_one` / `players_other` com `{{count}}`. Não monte plural com `if`.
- Valores dinâmicos por interpolação (`t("lobby.minPlayers", { min })`), não por concatenação.
- Erros do servidor chegam como `{ code, params }` e são traduzidos pela chave `errors.<code>`. Código novo no backend exige `errors.<CODE>` nos dois idiomas; `errors.UNKNOWN` é o fallback.
- Chaves dinâmicas como ``t(`roles.${role}.name`)`` são aceitas quando o sufixo é um enum; mantenha todos os valores possíveis nos arquivos.
- O idioma é trocado pelo `LanguageSwitcher`, persistido em `localStorage` (`language`) e refletido em `document.lang`.
